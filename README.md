# 96_Policies

내가 만든 앱·확장·서비스의 **개인정보처리방침을 한곳에서 관리하는 저장소**.

GitHub Pages 로 공개해 각 정책에 영구 URL을 준다. 스토어 심사는 등록 이후에도
정책 페이지를 다시 열어보므로, 링크가 계속 살아있어야 하고 내용이 제품과 맞아야 한다.

## 왜 이 저장소가 필요한가

정책을 제품마다 흩어놓으면 두 가지가 깨진다.

- **링크가 사라진다.** 노션 워크스페이스를 옮기거나 지우면 심사 중인 앱의 정책 URL이 죽는다
- **내용이 어긋난다.** 다른 제품 정책을 재사용하면 스토어에 신고한 수집 항목과 문서가 모순된다.
  실제로 광고 SDK를 쓰는 앱의 정책을, 아무것도 수집하지 않는 확장에 그대로 쓰려다 걸렸다

한 저장소에 모아두면 변경 이력이 남고, 어떤 제품이 어떤 정책을 쓰는지 한눈에 보인다.

## 구조

```
index.html                 정책 목록
privacy/<제품-slug>.html    제품별 정책 페이지
assets/style.css           공통 스타일
```

`<제품-slug>` 는 배포처에서 쓰는 식별자와 맞춘다. 예: `tutor-scheduler-ext`.

## 규칙

1. **제품 하나에 문서 하나.** 다른 제품 정책을 재사용하지 않는다
2. **스토어에 신고한 수집 항목과 문서가 일치해야 한다.** 둘 중 하나만 고치면 반려된다
3. 모든 문서에 **제품명과 최종 수정일**을 적는다. 심사자가 이 문서가 그 제품 것인지 확인한다
4. 내용을 고치면 최종 수정일을 갱신한다
5. 게시 후 **시크릿 창으로 열어 로그인 없이 보이는지 확인한다**
